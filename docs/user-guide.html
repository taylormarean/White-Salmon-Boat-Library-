01The big picture

The system has three parts that work together:

PartWho uses itWhat it does
Marketing siteThe publicThe pitch: what the library is, the river rules, become-a-member, volunteer and donate calls to action.
Member appMembersSelf-serve everything: join with the waiver, check out gear 24/7, get the shed code, return with a condition report, claim volunteer shifts.
Staff dashboardLibrarians & adminsThe same app with more doors: inventory, repairs, member roster, checkout board, schedule, incidents, settings.
The core idea
The shed stays open 24/7 with nobody behind a counter, because every safeguard the paper system relied on a human for — the waiver, the checkout board, the buddy rule, the honesty about damage — is enforced by the software instead.

02For members

Joining the library

  1. On the website, choose Become a member — it's free.
  2. Fill in your contact info, an emergency contact (required), and your whitewater experience level. Be honest — "new to whitewater" just means the app will ask who you're paddling with.
  3. Read the liability waiver and sign it by typing your full legal name. There is no membership without a signed waiver — the system won't create the account.
  4. You'll get a welcome email with the orientation schedule. Orientations are Tuesdays, 5:30pm at the shed (The Missing Corner, BZ Corner — across from the Mini Mart). New paddlers: come to one before your first checkout.

Checking out gear

1

Pick your gear

Everything available right now, by category. Each item shows the code on its physical tag, brand/model, color, size, and condition. Up to 6 items.

2

Pick a return date

Up to 7 days out. Optionally tell us where you're paddling — it helps if something goes wrong.

3

The agreement

Four checkboxes, each a real rule: sober on the river, PFD on the water, buddy named if you're new, honest damage reports.

Hit the button and your shed access code appears on screen — and lands in your email. Take exactly the gear on your checkout, close the shed, scramble the lock.

The app will stop you if…
…you have overdue gear out · your waiver is out of date (re-sign and continue) · your membership is suspended · someone grabbed an item seconds before you (refresh and re-pick) · any acknowledgment is missing.

While you're out

My Gear shows everything you have out, the due date, and your shed code in case you forget it. You'll get a friendly reminder email the day before gear is due.

Returning gear

  1. Bring everything back clean and drained.
  2. In My Gear, hit Return gear and rate each item: Good shape or Damaged.
  3. Damaged items need a short description — mandatory, and here's the deal: nobody is ever charged for honestly reported damage. Your note goes straight to the repair queue so the next member never takes out unsafe gear.

Overdue gear blocks new checkouts and triggers reminder emails (day before, day after, and a week after — at which point a librarian is notified). Need more time? Ask — extensions take seconds.

Volunteering

The Volunteer page lists upcoming shifts — orientation nights, repair nights, inventory audits. Claim shift to sign up, Drop shift if plans change. Shifts show who else is coming and close when full.

03For librarians

Staff accounts see the member app plus the operational pages.

Dashboard

The at-a-glance page: gear available / checked out / overdue / in repair, active members, open incidents, everything currently out with due dates, the repair queue, and upcoming shifts. Every tile is clickable.

Inventory

  • Add or edit gear — code (write it on the physical item), category, brand/model, color, size, condition.
  • Log issue — minor keeps the item in circulation; major/unusable pulls it automatically.
  • Pull / Restore — take an item out of circulation (reason required; members just see "In for repair") or put it back.
  • Repairs tab — the queue. Member damage reports land here automatically; resolving a ticket can return the item to service in the same action.

Members

The roster shows waiver status, orientation status, experience level, gear out, and overdues. Click into a member for full history, then:

  • Mark orientation done after a Tuesday session
  • Suspend / Reinstate — reason required; suspended members can't check out
  • Terminate for policy violations — also disables their login

Checkouts

The digital checkout board — Active, Overdue, Returned, and the Code log (every access code ever issued, to whom, when).

  • Extend — new due date; reminder emails re-arm automatically.
  • Force return — for gear back on the shelf but never marked returned, or lost gear. Items go back to circulation or to inspection, your choice.
  • Today's door code — in daily-code mode, the code to program into the shed keypad shows here.

Schedule & Incidents

Create volunteer shifts and watch signups fill. Log injuries, near-misses, gear damage, and policy violations with status tracking and follow-up notes.

04For admins

Users & roles

RoleCan do
adminEverything, including users and settings
librarianAll staff operations
volunteer / memberSelf-service + shift signup
disabledNothing (used for terminated memberships)

Role changes take effect immediately — the system re-checks the database on every request. Password resets happen here too. Safety rail: you can't demote or disable your own admin account.

Settings (live — changes apply instantly)

  • Loan limits — max days per loan, max items per checkout
  • Door code mode — per_checkout (each checkout gets a random code) or daily (one code per day; staff see it for programming the keypad, members only after a valid check-in)
  • Waiver version — bump the number and every member must re-sign before their next checkout. Use whenever the waiver text changes.
  • Notifications kill switch — pauses every outbound email at once, with a reason
  • Orientation info, library address, staff digest email

The paper trail

Three logs, all in the app: the audit log (every admin action — who, what, when), the notification log (every email sent or suppressed, and why), and the access code log (every shed code issued).

Donations

The website's Donate button opens a Stripe-hosted checkout — card details never touch the library's systems. Completed donations appear for staff with running totals. Until Stripe keys are configured, the button politely says donations aren't live yet.

05Behind the scenes

  • Reminder emails run hourly, three waves per checkout, each sent at most once: due-soon (24h before) → overdue (past due; also blocks new checkouts) → week-overdue (firmer note + staff digest). Extending a due date resets the waves.
  • Access codes — every issuance is logged. Per-checkout mode gives each member their own random 6-digit code; daily mode derives one code per day from a secret key, so staff can program the lock ahead of time.
  • Damage triage — a "damaged" report instantly pulls the item from circulation and opens a repair ticket. There is no gap where unsafe gear is borrowable.
Security, in one paragraph
Passwords are properly hashed, logins are rate-limited, staff pages verify the caller's role against the database on every request, members can only touch their own checkouts, and every sensitive action lands in a log. A full security review ships with the codebase.
